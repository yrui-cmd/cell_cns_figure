# cell_cns_fig1

文字或图片 → 固定接口 → 独立 Python 等待 → SVG 返回 → 原聊天继续 → 可编辑 PPT / AI。

## 输入与显示

- 支持文字、图片或图文一起，至少提供一项；都没有时只问“请发文字或图片。”不提交、不扣费。图片为真实 PNG/JPG，最大10 MiB；PDF先按用户选定页转成图片。保留用户原文，未提供的输入留空。
- 用户可以选择“PPT”或“Adobe Illustrator（AI）”。只在目标未确定时问“用 PPT 还是 Adobe Illustrator？”已给出的选择直接沿用，分别对应application=ppt或ai；不能自行默认、改选或同时生成两种。已选软件暂不可用时保留任务，简短说明缺少的条件。
- 每个新任务成功接收一次扣20额度；轮询、下载、结果转换不再次收费。提交前查询真实可用额度；已经明确授权本图20额度时不重复确认，否则只问“本次20额度，做成PPT还是AI？”或在目标已确定时问“本次20额度，继续吗？”
- 接口写死在脚本中，没有地址配置或切换入口。只使用客户 API Key，不能使用后台接单或管理员密钥。
- 正常运行时，进度消息只能是“正在第1步。”至“正在第5步。”，不附步骤名称、解释、计划、技术细节或统计。只在进入新步骤时提示一次；等待期间没有变化不重复刷屏。任务ID、端点、路径协议、哈希、轮询日志和JSON留在后台；不要显示接口地址和密钥。
- 步骤固定：第1步准备输入和选择；第2步提交；第3步后台等待；第4步将收到的SVG映射到所选软件；第5步保存交付。后台返回原聊天后从第4步继续，不重新显示第1至3步。共享资源占用时保持当前步骤。
- 必要的缺图、选择、API Key、20额度确认和真实错误允许一句简短提示；不得用步骤提示掩盖失败。最终只显示“完成。”和所选文件链接。预览、原SVG、剩余额度和过程详情仅在用户需要时附上。
- 本Skill与cell-cns-figure只共享“发送后接收”的思路，不执行它的A/B阶段或10/45额度规则；与cell_su7只共享SVG后处理，不执行图像识别、去字、去水印或额外付费接口。

## 提交并结束当前轮

使用本机已安装的 Python（例如命令 `python`）。调用与恢复命令见[客户端运行](references/client.md)。

1. 显示“正在第1步。”，保存提供的原图；提供的文字写UTF-8文件。给任务选择独立目录，记录当前真实`CODEX_THREAD_ID`，禁止猜聊天ID、另建聊天或发到姐妹聊天。
2. 核对选择与20额度授权，运行`client.py probe`确认桌面原聊天可达。先执行`discover-key`本地检测已有 API Key，再用`balance`查看实时余额。已有配置直接复用，只有明确未找到时才问“请提供小描 API Key。”；用户可在聊天提供，通过stdin交给`configure-key`，不复述或写到命令行。凭据只存当前Windows用户DPAPI密文；本机已有客户凭据可直接使用，不替换账号。
3. 显示“正在第2步。”，执行`submit --application ppt|ai --job-dir ... --credits-approved 20 --authorize-wake`，有图加`--image`，有文字加`--text-file`，至少提供一项。调用者传入当前真实thread-id。启用本Skill处理该任务包含用户要求的“结果返回后通知原聊天继续处理”授权；不得扩大到别的聊天。
4. 脚本持久化原图与请求ID，注册登录/崩溃恢复，提交后自动启动独立Python等待进程。确认返回`charged_credits=20`且`background_waiter_verified=true`；仅回复“正在第3步。”并结束本轮。
提交后使用返回的`progress_url`调用`open_in_codex`，在当前聊天右侧打开本地进度面板（browser目标）。面板按1小时预估自动推进，结果未保存校验前最多99%；接收器已保存并校验SVG才到100%。等待期间结束模型轮次，让后台Python继续；不要为更新进度反复调用模型、发送聊天消息或轮询网站。面板未启动时仅运行`client.py progress --job-dir <原目录>`恢复，不重新提交订单。

5. 响应丢失只恢复原目录、原请求ID；不能换目录重新提交、重复付费。接收进程在后台检查原任务，收到SVG后下载、校验并保留，再通过桌面工具通知原聊天。原聊天正忙则等待空闲。

仅创建/更新/安装本Skill时不上传图片、不查询客户业务余额、不创建付费测试订单。可以做隔离本地测试和只读桌面连接检查。

## 结果返回后

1. 先读回执中的原任务目录与job.json，核对当前聊天就是记录的原聊天。执行`client.py acknowledge --job-dir ... --nonce ...`确认接收；不会再次发送订单。
2. 结果未通过SVG校验或回执是需要处理的状态时，报告实际原因并保留原任务，不把错误当完成，不重新收费。共享资源暂时占用时等待后继续。
3. SVG有效时只显示“正在第4步。”然后执行`client.py convert --job-dir ...`。按用户指定的直接路径映射模式：复用cell_su7的路径解析与原生PPT/AI写入，不再做裁剪兼容检查、隐藏对象剔除或重绘；禁止从图片入口重新识别。见[SVG后处理](references/postprocess.md)。
4. PPT在Windows中默认制作原生可编辑PPTX，再在隔离副本中逐路径显示并导出实际PowerPoint预览。用户明确只要文件时使用`--file-only`。AI沿用已打开目标文档的原生对象重建，保存AI并导出PNG；不得修改已有无关对象。
5. 显示“正在第5步。”，查看实际输出预览，确认文件已生成、路径是原生可编辑对象；不要求效果一致性修复或逐对象科学审查。确认后`client.py complete --job-dir ... --visual-checked`。
6. 最终只显示“完成。”和所选PPTX或AI文件链接。内部规则：直接映射保留原始坐标、变换、顺序及复合子路径，裁剪/蒙版/滤镜不参与，渐变取首色、虚线沿原路径实线映射，曲线文字作为锚点处普通文字，PPT使用其原生复合填充；不声称与SVG渲染完全一致。原件不改，不栅格化，不重新识别或收费。

## 恢复边界

无窗口Python接收器持续等待，登录时直接启动的pythonw常驻监控器负责恢复；不周期性启动PowerShell或控制台，不创建Codex定时唤醒、不在聊天长时间sleep。重启后需登录当前Windows账号并让Codex桌面可用；密钥失效、显式停止或72小时本地等待超时会通知原聊天，不声称远端已取消或退款。正常无变化保持安静。

唤醒响应不明时保存`wake_uncertain`，先检查原聊天回执，不盲目重复发送；读取本地原结果后可在原聊天继续acknowledge/convert。用户明确停止时执行stop，保留原图、已返回SVG和远端订单；恢复沿用原任务。
