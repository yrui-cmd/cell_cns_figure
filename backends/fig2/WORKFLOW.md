# cell_cns_fig2

开场和结尾必须显示合并入口 `SKILL.md` 的固定提示；本分支的简短显示规则不省略这两处提示。
文字 / 图片 / 图文 → Figure Pro 固定接口 → 独立 Python 等待 → SVG 返回 → 原聊天继续 → 可编辑 PPT / AI。

## 输入与显示

- 文字、单张真实PNG/JPG图片或图文均可，图片最大10 MiB，文字最多500000字符。两者皆无只问“请提供文字或图片。”不提交、不扣费。PDF先按用户选定页转成图片。只有图片时不强制索要文字；只有文字时不要求补图，服务端由cell_gra_pro1执行素材采集与绘图流程，不在客户端额外生图或收费。保留客户原文，不扩写科研内容。
- 只在目标未确定时问“PPT 还是 AI？”已给出的选择直接沿用。
- 每个新任务成功接收一次扣45额度；轮询、下载、结果转换不再次收费。提交前查询真实可用额度；已经明确授权本图45额度时不重复确认，否则只问“本次45额度，做成PPT还是AI？”或在目标已确定时问“本次45额度，继续吗？”
- 接口写死在脚本中，没有地址配置或切换入口。只使用客户 API Key，不能使用后台接单或管理员密钥。
- 面向用户精简显示：缺少输入、费用确认、提交成功、正在转换、最终文件。任务ID、端点、路径协议、哈希、轮询日志和JSON留在后台；不要显示接口地址和密钥。
- 本Skill固定连接figure_pro的45额度服务；与cell-cns-figure只共享“发送后接收”的思路，不执行它的A/B阶段或10/45额度规则；SVG后处理代码已从cell_su7内置到本Skill，不执行图像识别、去字、去水印或额外付费接口。

## 提交并结束当前轮

使用本机已安装的 Python（例如命令 `python`）。调用与恢复命令见[客户端运行](references/client.md)。

1. 保存已有图片；文字有则写UTF-8文件。给任务选择独立目录，记录当前真实`CODEX_THREAD_ID`，禁止猜聊天ID、另建聊天或发到姐妹聊天。
2. 核对选择与45额度授权，运行`client.py probe`确认桌面原聊天可达。先执行`discover-key`本地检测已有 API Key，再用`balance`查看实时余额。已有配置直接复用，只有明确未找到时才问“请提供小描 API Key。”；用户可在聊天提供，通过stdin交给`configure-key`，不复述或写到命令行。凭据只存当前Windows用户DPAPI密文；本机已有客户凭据可直接使用，不替换账号。
3. 新订单先取得一次性邀请码并说明“使用一次即失效，余额不足也失效；成功接单仍扣45额度”。已提供码则不再索要。执行`submit [--image ...] [--text-file ...] --application ppt|ai --job-dir ... --credits-approved 45 --authorize-wake --invite-stdin`；纯文字省略`--image`，纯图片省略`--text-file`，至少有一个有效输入。通过进程标准输入传入一行邀请码，不把码写进命令参数、脚本文件或日志。调用者传入当前真实thread-id。启用本Skill处理该任务包含用户要求的“结果返回后通知原聊天继续处理”授权；不得扩大到别的聊天。
4. 脚本持久化输入与请求ID，注册登录/崩溃恢复，提交后自动启动独立Python等待进程。确认返回`charged_credits=45`且`background_waiter_verified=true`；再告知“已提交，结果返回后自动继续。”并结束本轮。
提交后脚本自动在原聊天右侧创建并打开本地进度面板，返回`progress_opened=true`；无需模型另行打开。面板按1小时预估自动推进，结果未保存校验前最多99%；接收器已保存并校验SVG才到100%。等待期间结束模型轮次，让后台Python继续；不要为更新进度反复调用模型、发送聊天消息或轮询网站。面板未启动时仅运行`client.py progress --job-dir <原目录>`恢复，不重新提交订单。

5. 响应丢失只恢复原目录、原请求ID；不能换目录重新提交、重复付费。接收进程在后台检查原任务，收到SVG后下载、校验并保留，再通过桌面工具通知原聊天。原聊天正忙则等待空闲。

仅创建/更新/安装本Skill时不上传图片、不查询客户业务余额、不创建付费测试订单。可以做隔离本地测试和只读桌面连接检查。

## 结果返回后

1. 先读回执中的原任务目录与job.json，核对当前聊天就是记录的原聊天。执行`client.py acknowledge --job-dir ... --nonce ...`确认接收；不会再次发送订单。
2. 结果未通过SVG校验或回执是需要处理的状态时，报告实际原因并保留原任务，不把错误当完成，不重新收费。共享资源暂时占用时等待后继续。
3. SVG有效时执行 `client.py convert --job-dir ...`，使用本 Skill 内置 SVG→原生 PPT/AI 流程。禁止临时调用其他 Skill、重新识别图片或复用旧版错位输出。见 [SVG后处理](references/postprocess.md)。
4. PPT在Windows中默认制作原生可编辑PPTX，再在隔离副本中逐路径显示并导出实际PowerPoint预览。用户明确只要文件时使用`--file-only`。AI沿用已打开目标文档的原生对象重建，保存AI并导出PNG；不得修改已有无关对象。
5. 查看实际输出预览，确认文件已生成、路径是原生可编辑对象；不要求效果一致性修复或逐对象科学审查。确认后`client.py complete --job-dir ... --visual-checked`。
6. 实际预览确认位置、比例、箭头和文字正常后完成验收，最终仅返回用户选择的文件链接。错误时保留原 SVG、转换日志和已有进度，不能将缺素材或错位结果交付为完成。

## 恢复边界

无窗口Python接收器持续等待，登录时直接启动的pythonw常驻监控器负责恢复；不周期性启动PowerShell或控制台，不创建Codex定时唤醒、不在聊天长时间sleep。重启后需登录当前Windows账号并让Codex桌面可用；密钥失效、显式停止或72小时本地等待超时会通知原聊天，不声称远端已取消或退款。正常无变化保持安静。

唤醒响应不明时保存`wake_uncertain`，先检查原聊天回执，不盲目重复发送；读取本地原结果后可在原聊天继续acknowledge/convert。用户明确停止时执行stop，保留原图、已返回SVG和远端订单；恢复沿用原任务。

异常原因解决后，在原聊天用resume恢复原订单；若SVG已经保存，按返回的next_action继续convert。1号与2号任务目录不能混用；凭据沿用任务内记录的同一客户。具体恢复步骤见[客户端运行](references/client.md#异常恢复)。

## 每单一次性邀请码

每个新任务需要用户提供一个 Figure Pro 邀请码，支持 `Cell_Pro` 后6–32位字母或数字（如 `Cell_Projkldjd`，区分大小写），兼容旧 `fgp_inv_...` 码；客户端不创建或猜测邀请码。邀请码仅作为一次提交许可，仍扣45额度。仅在新任务缺少邀请码时简短询问；已有订单查询、下载、回传和转换不再索要。不要将邀请码当作API Key、余额充值或长期授权。

提交时加 `--invite-stdin`，从标准输入传入一行邀请码，不放在命令参数或日志。邀请码以本Windows用户DPAPI密文保存到任务状态，用于同一 request_id 的断线恢复。仅 Pro（45额度）需要邀请码。有效码提交使用一次即失效，余额不足也消耗；余额不足不扣费、不创建任务，补足额度后需新码。提交前说明此规则；用户已授权提交时，不因余额不足在本地拦截。输入格式错误或系统事务失败不消耗，已受理订单重试不重复扣费。

未取得订单号且需要补充或更换无效邀请码时，只在原聊天运行 `set-invite --job-dir <原目录>`，从标准输入传码，然后 `resume --job-dir <原目录>`。保留原 request_id、输入与账户，不能为重试新建收费任务。已取得订单号时不允许改邀请码。

返回402时明确告知“余额不足，本次邀请码已失效，未扣费、未创建任务”；不要自动循环提交或自动换码。待用户提供新码并授权继续后，在原目录补码恢复。仅查询余额、等待、下载或转换不消耗邀请码。
